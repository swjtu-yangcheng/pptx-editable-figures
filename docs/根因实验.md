# 根因实验：浮点 EMU 坐标如何导致箭头漂移

## 现象

用 python-pptx 画的流程图，坐标算得没错，但 PowerPoint 里打开后箭头位置跑偏——
不在两个框之间，而是飘到画布别处。

## 排查

导出 PPTX 的连接线 XML：

```xml
<p:cxnSp>
  <a:xfrm>
    <a:off x="2414811.5" y="2697480.0"/>    ← 浮点
    <a:ext cx="2211060.0" cy="0.0"/>
```

坐标是**浮点**的。OOXML 规范要求 EMU 坐标必须是整数。

来源：脚本里写了画布居中计算 `(slide_width - total_w) / 2`。
Python 的 `/` 产生 float，而 python-pptx **不做取整直接写入 XML**。

## 验证：控制变量实验

不能靠猜，做实验。取同一份正常的 PPTX，只改连接线的 `a:off/@x`：

| 样本 | 处理 | PowerPoint 打开 |
|---|---|---|
| A | 原始（整数坐标） | ✅ 成功 |
| B | 加 0.5 得浮点 | ❌ **失败** |
| C | 同值取整回退 | ✅ 成功 |
| A' | 原始复测 | ✅ 成功 |

B 失败、C 成功，差值仅是取整 —— 因果成立。

实验代码（要点）：

```python
def make(path, mode):
    p = Presentation(src)
    for sp in p.slides[0].shapes:
        if sp._element.tag.endswith('cxnSp'):
            off = sp._element.find('.//' + qn('a:off'))
            v = float(off.get('x'))
            off.set('x', str(v + 0.5) if mode == 'float' else str(int(round(v + 0.5))))
    p.save(path)

app = win32com.client.Dispatch('PowerPoint.Application')
for tag, path in [('A', src), ('B', f_float), ('C', f_int), ('A复测', src)]:
    try:
        pres = app.Presentations.Open(path, WithWindow=False); pres.Close()
        print(tag, '成功')
    except Exception as e:
        print(tag, '失败', e)
app.Quit()
```

### 一个必须避开的实验陷阱

COM 调用要在**同一会话**内完成。若每个文件各起一个进程依次 `Dispatch` → `Quit`，
会出现"第一个成功、后续全失败"的假象，容易误判成别的原因。
比对多个文件务必在同一 `PowerPoint.Application` 实例内依次打开。

## 为什么这是静默失败

PowerPoint 并非每次都直接报错。多数情况下它容错打开，
把非法坐标的形状**回退到默认位置**——文件能开，图却是错的。
所以不主动校验根本发现不了。

## 修复与防御

1. **底层强制整数**：所有坐标经 `E()` / `inch()` 转换时 `int(round(x))`。
2. **提供 `arrow_between()`**：框到框自动贴合边缘，避免手算端点（手算也容易算错）。
3. **几何自检 `verify()`**：扫描全文档，检出浮点坐标、越界图元、未贴合的箭头端点。
4. **字符画预览**：数值正确不等于视觉正确，渲染后转文本再确认一次。

## 教训

- 涉及文件格式规范时，**先查规范再写代码**，别假设库会帮你兜底。
- 静默失败比报错更危险，必须配主动校验。
- 定位根因要用控制变量实验，而不是"改改看好了没"。
